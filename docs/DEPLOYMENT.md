# Deploy QuizFlow

## Render Blueprint

The included `render.yaml` defines a Docker web service and a private PostgreSQL database. Review your chosen plans in the dashboard before creating resources; no free-tier or pricing assumptions are encoded.

1. Create a GitHub repository and push the project from the root `quizflow` directory:

```bash
git init
git add .
git commit -m "Build QuizFlow full-stack quiz platform"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/quizflow.git
git push -u origin main
```

Replace `YOUR_USERNAME` and create that repository first. `.env` and `node_modules` are ignored. The ZIP contains no real secrets.

2. In Render, create a **Blueprint** connected to the repository. Select the supplied `render.yaml`.
3. Set `APP_ORIGIN` to the service's final **HTTPS** address with no trailing slash, for example `https://your-quizflow-service.onrender.com`. Update and redeploy after the actual address is assigned if it differs from the initial value.
4. `JWT_SECRET` is generated by the Blueprint. `DATABASE_URL` comes from the Blueprint database's internal connection string. `TRUST_PROXY=1` assumes the service is behind Render's single trusted reverse proxy.
5. The app initially uses `AI_PROVIDER=demo`. To enable custom AI questions, set `AI_PROVIDER=gemini` and `GEMINI_API_KEY` in the service's environment settings. Set `GEMINI_MODEL` to an available model.
6. Confirm `/api/health` returns `status: ok`, then test with one teacher and two independent student browsers. Check sign-in, reconnect, reveal, final results and CSV export.

Source: https://render.com/docs/blueprint-spec

Keep one web-service instance. The API automatically applies the additive v1 schema on boot. Configure database backups in your database provider; future schema evolution should use versioned migrations.

## Any Docker host with managed PostgreSQL

From the project root:

```bash
docker build -t quizflow:1 .
```

Supply the following as **runtime** variables through your hosting dashboard or private environment file (never commit secrets):

```dotenv
NODE_ENV=production
PORT=3000
APP_ORIGIN=https://your-domain.example
DATABASE_URL=postgresql://user:password@your-db-host:5432/database
JWT_SECRET=your_random_64_character_hex_secret
AI_PROVIDER=gemini
GEMINI_API_KEY=your_private_key
GEMINI_MODEL=gemini-3.8-flash
TRUST_PROXY=1
```

Set `DATABASE_SSL=true` if your database requires TLS with a publicly trusted CA. Supply the provider's verified SSL URL/CA setup if it uses a private CA. Certificate verification is not disabled in this project. An internal private database URL can use the provider's documented internal connection settings.

Route HTTPS and WebSocket upgrades to container port 3000. Set `TRUST_PROXY` to the actual trusted proxy hop count; keep 0 for direct access. Serve the app and API on the same origin. Do not split the frontend and backend without adapting cookie, CORS and CSRF behavior.

For a private environment file on your host:

```bash
docker run --rm --env-file /absolute/path/to/quizflow-production.env -p 3000:3000 quizflow:1
```

Expose this only behind the configured HTTPS reverse proxy. Do not set `LOCAL_DOCKER=true` publicly.

## Troubleshooting

- **npm ENOENT/package.json missing:** `pwd` and `ls`; enter the extracted `quizflow` directory. This project uses one root install and one root dev command.
- **Database connection refused:** start Docker Desktop and run `docker compose up -d db`. Use `docker compose logs db` and `docker compose ps`.
- **Port 5432 already in use:** stop the existing database or change the compose host port and matching `DATABASE_URL`.
- **Invalid JWT secret:** generate it with `npm run setup` after removing only the placeholder line/file. The placeholder is intentionally rejected.
- **Untrusted request origin:** match `APP_ORIGIN` to the exact browser origin; omit trailing slashes and restart the API.
- **Blank frontend:** use `npm run dev` and http://localhost:5173, not Live Server. Production requires `npm run build` before starting the API.
- **Gemini model unavailable:** pick a model your AI Studio account can use; do not assume an older model remains available.
- **Gemini quota exceeded:** inspect AI Studio quota/billing. The app reports the failure and does not substitute fake AI results.
- **Participant cannot resume:** browser cookies expire after seven days. A new browser cannot take over another participant's identity.
- **Host action conflicts:** another participant may have changed the session version. Wait for refresh and retry; stale controls are rejected to avoid double advancement.
